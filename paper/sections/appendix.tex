\section{Leakage Audit}
\label{app:leakage}
We verify four causal-ordering invariants programmatically over the raw run logs
of the fused experiment (audit script released with the code):
\textbf{(A)} every problem is scored exactly once (after de-duplicating
checkpoint-resume rows); \textbf{(B)} no memory entry predates its problem's
scoring batch---the scored generation can never see its own hint; \textbf{(C)}
memory is append-only with respect to the stream, so retrieved demonstrations
always come from strictly earlier batches; \textbf{(D)} aggregate counters match
the per-problem log exactly. All checks pass on the actual run artifacts. Gold
labels exist only inside the 0/1 oracle; the stored hint is always the model's
own earlier oracle-passing output, never a dataset field.

\paragraph{Example trace.} For a streamed problem, the student prompt contains
the system prompt, three retrieved (question, verified-answer) pairs from
earlier problems, and the new question---nothing else. The teacher prompt is the
identical message list plus one assistant turn containing the model's own stored
answer and the question repeated. Full reconstructed traces (built by the
training code itself from run artifacts) are released alongside the code.

\section{Cost Accounting}
\label{app:cost}
Per problem, our method spends 1 scored oracle call plus ${\sim}8.8$
re-evaluation calls (window re-answers whose only effect is memory update);
measured on the fused run: 24{,}450 total calls for 2{,}490 problems at the
point of measurement (${\sim}9.8$/problem). Base, ICL, and REINFORCE++ use
exactly 1 call per problem; batch SDFT uses 1 per problem per epoch. Wall-clock
on one H200: standalone streams ${\sim}$8--14\,h; the fused 4{,}219-problem run
${\sim}$30\,h of compute (checkpoint-resumable in preemptible 4\,h slices);
batch SDFT (4 epochs) ${\sim}$3.5\,h; a bare-prompt evaluation pass
${\sim}$40\,min. \todo{Finalize GPU-hour table per run.}

\section{Additional Ablation Detail}
\label{app:ablations}
\paragraph{Generation source.} DS-1000 standalone, full 955: bare-prompt
generation (offline-SDFT default) $.436$ acc / 539 regret vs hint-conditioned
$.423$ / 551; the gap accumulates in the last third of the stream. Fused stream
(stopped at 1{,}820 of 4{,}219 by design): bare-prompt loses ${\sim}10$ regret
in the first 300 problems, then tracks even for 1{,}500 problems.
\paragraph{Epochs and learning rate.} DS-1000, matched settings: 4 epochs
$-21$ cumulative regret vs 2 epochs; 2 epochs at doubled lr $+5$ regret vs
2 epochs---epochs do what lr cannot.
\paragraph{Multi-sample distillation.} $N{=}10$ teacher-conditioned samples per
problem, similarity-filtered ($\mathrm{sim} \ge 0.5$ to hint) or unfiltered:
both statistically indistinguishable from $N{=}1$ on DS-1000 (filtered: 186 vs
188 regret at 300 problems; unfiltered: mildly negative over 520 problems).

\section{Per-Task Prompts}
\label{app:prompts}
Every task uses the same message structure (\S\ref{sec:method}); only the
system prompt and question formatting differ. Representative system prompts:

\begin{itemize}
\item \textbf{DS-1000 / code}: \emph{``You are an expert Python programmer for
data science. Solve the problem by writing correct Python code. Output ONLY the
code in a \texttt{```python ...```} block.''}
\item \textbf{DDXPlus}: \emph{``You are an expert medical doctor making a
differential diagnosis.''} The question presents a patient profile and the
49-option diagnosis list; the answer format is \texttt{<number>. <diagnosis>}.
\item \textbf{HotpotQA}: \emph{``You are a careful assistant answering
multi-hop questions with short, exact answers in JSON.''} The question includes
the 10-paragraph distractor context; the answer format is
\texttt{\{"answer": "<span>"\}}.
\end{itemize}

A complete worked trace (retrieval, student prompt, generated answer, oracle
grade, storage, and the teacher prompt's two additional turns) for one problem
per dataset is included in the released repository, reconstructed by the
training code itself from the run artifacts. SQL and tool-use templates follow
StreamBench's released prompts.
